## Registration state machine

Após limiter/normalize, claim active intent. Semantic HMAC cobre schema+normalized names, nunca senha. Pending identity verifica senha via scrypt antes de register; mismatch é zero-write. State `pending_identity -> pending_customer -> completed`; conforme 14-03 usa strong transaction somente quando comprovada, senão recovery state reconciliável. Completion cria uma initial lineage/refresh e verification intent+outbox; provider delivery não bloqueia.
